# 编译说明

需要 Python 3、JDK 17、Android SDK API 28 和 build-tools 34.0.0，无需 Gradle。

设置 `JAVA_HOME`、`ANDROID_HOME` 后运行：

```sh
python build.py
```

也可以指定工具路径：

```sh
python build.py --java-home "<JDK17目录>" --android-jar "<SDK>/platforms/android-28/android.jar" --build-tools "<SDK>/build-tools/34.0.0"
```

APK 输出到 `dist/E02-Starbox-v1.7.4.apk`。首次编译会生成 `.local/development.p12`，请保留此签名文件用于自行构建版本的更新；不同签名的 APK 无法直接覆盖安装。此默认产物使用开发签名，与既有车机和公开安装包的历史发布签名不同，不能直接覆盖它们。

维护者发布时需对 `build/aligned.apk` 使用既有发布密钥重新签名，再验证证书指纹、包名、版本、大小、SHA-256和zipalign。本地密钥位置及原签名构建入口保存在仓库忽略的 `.local/接续环境.md`，不得把私钥或密码放进公开交付。发布流程见[GitHub发布维护](GitHub发布维护.md)。

项目脚本现在支持直接原签名构建，不必依赖旧会话临时脚本：

```sh
rtk python build.py --java-home "<JDK17目录>" --android-jar "<android.jar>" --build-tools "<build-tools目录>" --signing-key "<既有发布密钥>" --signing-alias "<alias>" --signing-password-env E02_RELEASE_KEY_PASSWORD --output "<本次OUT目录>/E02-Starbox-v1.7.4.apk"
```

密码由指定环境变量提供，命令参数只包含变量名。传入的发布密钥必须已经存在；缺失密钥、alias或密码环境变量时构建直接报错，不能自动退回开发签名。`--output`允许把新候选直接放独立交付目录，避免覆盖旧验证批次。默认构建方式继续保持开发签名。

## 桌面测试

在 Windows 上运行：

```sh
python tests/run-tests.py --java-home "<JDK17目录>"
```

测试覆盖命令回传、连接码验证、超时、输出大小、授权撤销竞态与旧命令迁移和 ADB 命令范围。车辆连接需要在实车上确认。

## 源码目录

- `src/`：Android 源码、资源和网页终端。
- `tests/`：桌面测试。
- `compile-only/flyme/`：Flyme 状态栏接口的编译声明，不打包进 APK。
- `docs/`：使用指南及截图。
- `build.py`：编译和签名脚本。

## v1.7.0 手机助手

ZXing Core 3.5.3 已随源码保存在 `third_party/zxing/core-3.5.3.jar`，构建脚本自动加入编译及 D8 输入。其来源、SHA-256 和 Apache-2.0 许可证在同目录。二维码在车机离线生成，不依赖第三方二维码网站。

桌面协议测试包含 `TestPhone`，覆盖配对、焦点匹配、长文本、剪贴板事件、Host / Origin、会话失效及请求限制。
